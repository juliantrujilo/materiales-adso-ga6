3

Crea el repositorio local Programa-Git con su primer commit

Tiempo estimado: 10 min

La guía pide «añadirlo al repositorio local del programa» y, después, subir «los cambios del repositorio local». Para que haya algo que subir, tu repositorio local necesita al menos un commit. Aquí lo entendemos como un repositorio nuevo llamado Programa-Git (si ya tienes uno propio con historial, puedes usarlo; el video debe mostrar su historial).

preparar_programa_git_local.shGIT BASH
1# 1) Crea la carpeta del programa y entra en ella
2mkdir Programa-Git
3cd Programa-Git
4# 2) Inicia el repositorio local
5git init
6# 3) Crea un primer archivo y guarda la primera versión
7echo "# Programa-Git" > README.md
8git add README.md
9git commit -m "Primer commit del programa"
10# 4) Comprueba tu historial y el nombre de tu rama
11git log --oneline
12git branch

Qué hace cada comando

ComandoQué haceCómo se lee, parte por parte
mkdir Programa-GitCrea una carpeta nueva con ese nombre en la ubicación donde estás.mkdir = make directory: crear carpeta
el nombre = cómo se llamará la carpeta
cd Programa-GitEntra a la carpeta indicada. Desde ahí se ejecutarán los siguientes comandos.cd = change directory: cambiar de carpeta
el nombre = la carpeta a la que entras
git initConvierte la carpeta actual en un repositorio local: crea la carpeta oculta .git donde Git guarda el historial.git = el programa
init = iniciar un repositorio
echo "# Programa-Git" > README.mdCrea el archivo con ese texto dentro (si ya existía, lo reemplaza).echo = escribe un texto
> = en lugar de mostrarlo, lo guarda en un archivo
README.md = el nombre del archivo que se crea
git add README.mdPrepara el archivo para el próximo commit (lo pasa al staging).add = agregar al área de preparación
README.md = el archivo que preparas; con . se preparan todos
git commit -m "Primer commit del programa"Guarda una versión con lo que preparaste, con un mensaje que explica el cambio. Queda solo en tu equipo.commit = guardar una versión
-m = incluir el mensaje en el mismo comando
"mensaje" = qué cambiaste, entre comillas
git log --onelineLista el historial de commits, uno por línea: su código corto y su mensaje.log = mostrar el historial
--oneline = formato resumido de una línea por commit
git branchLista las ramas de tu repositorio y marca con asterisco la actual. Así sabes si tu rama es main o master.branch = trabajar con ramas; sin más opciones, solo las lista

Lo esperado: git log --oneline muestra una línea con tu commit y git branch muestra tu rama con un asterisco (probablemente main).

Si usas Windows PowerShell 5.1: el símbolo > guarda el archivo en UTF-16 y GitHub puede mostrarlo raro. Usa Git Bash o crea el archivo así: Set-Content -Path README.md -Value "# Programa-Git" -Encoding utf8.
Verifica que funciona antes de seguir
  • La carpeta Programa-Git existe y tiene git init.
  • git log --oneline muestra mi primer commit.
  • Sé cómo se llama mi rama (git branch).
4

Decide tus nombres: remoto y rama

Tiempo estimado: 6 min

Aquí se resuelve la confusión más común de este ejercicio. La guía usa github como nombre del remoto en los pasos 1 y 2 (git remote add github url, git push github master) y origin en el paso 3 (git push origin master). Si copias los tres pasos tal cual, el tercero falla con 'origin' does not appear to be a git repository. Además, la guía habla de master, pero tu rama probablemente se llama main.

TemaRuta recomendadaRuta literal de la guía
Nombre del remotoorigin en los tres pasosgithub en los tres pasos (incluido el paso 3)
Nombre de la ramaEl que muestre git branch (normalmente main)master, solo si tu rama se llama así (o la renombras)
Paso 1git remote add origin URLgit remote add github URL
Paso 2git push -u origin maingit push -u github main
Paso 3git push origin maingit push github main

Los puntos finales de la guía (git push origin master.) son puntuación del texto: no los escribas. El nombre del remoto y de la rama no cambian el resultado: lo importante es que uses el mismo remoto en los tres pasos y que lo digas en el video.

nombres_remoto_y_rama.shGIT BASH
1# Muestra tu rama actual (la del asterisco)
2git branch
3# Opcional: cambia el nombre de tu rama
4git branch -M main
5# Si ya creaste un remoto llamado github y quieres usar origin
6git remote rename github origin

Qué hace cada comando

ComandoQué haceCómo se lee, parte por parte
git branchLista las ramas de tu repositorio y marca con asterisco la actual. Así sabes si tu rama es main o master.branch = trabajar con ramas; sin más opciones, solo las lista
git branch -M mainRenombra la rama actual a main para que coincida con la de GitHub.branch = trabajar con ramas
-M = renombrar la rama actual aunque ya exista otra con ese nombre
main = el nombre nuevo
git remote rename github originCambia el nombre de un remoto ya creado, sin borrar la conexión.remote rename = renombrar un remoto
github = el nombre actual
origin = el nombre nuevo
Frase para decirlo en el video
Uso el remoto llamado origin y la rama main. En la guía aparecen github y master, pero son solo nombres distintos para lo mismo: el remoto es la dirección de GitHub y la rama es la línea de versiones de mi proyecto.
Decisión del instructor: la ruta recomendada es una sugerencia para evitar el error. Si tu instructor prefiere la ruta literal, úsala y mantenla en los tres pasos.
Verifica que funciona antes de seguir
  • Elegí un solo nombre de remoto para los tres pasos.
  • Sé cómo se llama mi rama y usaré ese nombre en los push.
  • Tengo lista la frase para explicarlo en el video.
5

Crea el repositorio remoto público Programa-Git

Tiempo estimado: 6 min

Este es el primer punto del Paso 1 de la guía: «crear un nuevo repositorio público ... con el nombre Programa-Git». Se hace en el navegador:

  1. Entra a github.com con tu sesión iniciada. Abre el menú + (arriba a la derecha) y elige New repository.
  2. Repository name: escribe exactamente Programa-Git.
  3. Visibilidad: marca Public.
  4. Déjalo vacío: NO marques Add a README file, .gitignore ni licencia.
  5. Presiona Create repository y, en la sección Quick setup, selecciona HTTPS y copia la URL (termina en .git). La guía dice «copiar su url con el protocolo https».
Error frecuente: crear el repositorio con README. Después Git rechaza el push con rejected ... fetch first o unrelated histories, porque los historiales son distintos. Si te pasa, crea un repositorio vacío nuevo.
En el video: muestra esta pantalla con el nombre Programa-Git y la opción Public marcadas, y di por qué lo dejas vacío (porque el local ya tiene historial).
Verifica que funciona antes de seguir
  • El repositorio Programa-Git existe en mi cuenta de GitHub y es público.
  • Está vacío (sin README).
  • Copié la URL HTTPS.

Paso 1 de la guía: conecta el local con el remoto

Tiempo estimado: 8 min

Con la URL copiada, ejecutas los puntos 2 y 3 del Paso 1 de la guía.

paso1_conectar_remoto.shGIT BASH
1# Dentro de la carpeta Programa-Git; cambia TU_USUARIO por el tuyo
2# 1) Añade el repositorio remoto al local (en la guía: git remote add github url)
3git remote add origin https://github.com/TU_USUARIO/Programa-Git.git
4# 2) Muestra todos los remotos configurados
5git remote -v

Qué hace cada comando

ComandoQué haceCómo se lee, parte por parte
git remote add origin https://github.com/TU_USUARIO/Programa-Git.gitConecta tu repositorio local con el repositorio Programa-Git de GitHub. Todavía no sube nada: solo guarda la dirección con un nombre.git remote = administra las conexiones con repositorios remotos
add = agregar una conexión nueva
origin = el nombre corto de la conexión; en la guía se llama github en los pasos 1 y 2
https://github.com/TU_USUARIO/Programa-Git.git = la URL HTTPS del repositorio; cambia TU_USUARIO por tu usuario
git remote -vMuestra las conexiones remotas guardadas y sus URL. Comprueba que el origin quedó bien escrito.remote = conexiones remotas
-v = verbose: muestra también las URL (fetch para bajar, push para subir)

Lo esperado: git remote add no imprime nada si salió bien. git remote -v muestra dos líneas con tu nombre de remoto y tu URL, una terminada en (fetch) y otra en (push):

Salida esperada de git remote -v
origin https://github.com/TU_USUARIO/Programa-Git.git (fetch) origin https://github.com/TU_USUARIO/Programa-Git.git (push)
Si ves 'remote origin already exists': ya habías añadido el remoto. Revisa con git remote -v; si la URL está mal, corrige con git remote set-url origin URL.
En el video: di «con git remote add le digo a mi repositorio local dónde está el repositorio de GitHub, y con git remote -v compruebo que quedó registrado».
Verifica que funciona antes de seguir

Paso 2 de la guía: sube tus cambios y muestra el historial

Tiempo estimado: 8 min

Ahora ejecutas el Paso 2: agregar los cambios del repositorio local al remoto y comprobar en GitHub el historial de versiones.

paso2_push.shGIT BASH
1# 1) Mira el nombre de tu rama (la del asterisco)
2git branch
3# 2) Sube tus commits al remoto (en la guía: git push github master)
4git push -u origin main

Qué hace cada comando

ComandoQué haceCómo se lee, parte por parte
git branchLista las ramas de tu repositorio y marca con asterisco la actual. Así sabes si tu rama es main o master.branch = trabajar con ramas; sin más opciones, solo las lista
git push -u origin mainSube tus commits de la rama main a GitHub, y deja recordado que main de tu equipo sigue a origin/main.push = subir commits al remoto
-u = recuerda esta conexión para los próximos git push y git pull

Si Git pide autorización, se abrirá la ventana de Credential Manager o te pedirá usuario y token (Sesión 3, slide 11). El token se pega aunque no se vea nada. Cuida que no aparezca en el video. Lo esperado al final:

To https://github.com/TU_USUARIO/Programa-Git.git * [new branch] main -> main branch 'main' set up to track 'origin/main'.

  2. Presiona el enlace Commits (el icono del reloj con el número de commits) para abrir el historial de versiones y muéstralo.
Error frecuente: src refspec master does not match any. Tu rama se llama main: usa ese nombre.
