5

Describe el versionamiento local (indicador 2)

Tiempo estimado: 15 min

El segundo indicador pide describir las características del versionamiento local. Describir no es solo nombrar: explica cómo funciona y qué límites tiene. Estas son las características que debes cubrir:

  • Ubicación: vive en tu equipo, en la carpeta .git.
  • Disponibilidad: funciona sin internet y es rápido.
  • Historial: guarda cada commit con autor, fecha y mensaje.
  • Ramas: permite probar ideas sin tocar la versión principal.
  • Privacidad: nadie más lo ve hasta que lo compartes.
  • Límite: no es una copia de seguridad.
Características del versionamiento local (modelo)
El repositorio local de TechStore Pro vive en la carpeta .git de cada equipo. Permite registrar versiones con git commit sin conexión a internet, consultar el historial con git log y crear ramas para probar funciones nuevas sin afectar la versión principal. Es privado: solo su dueño lo ve hasta que decide publicarlo. Su límite es que no sirve como respaldo, porque si el equipo falla se pierde el historial.
Error frecuente: hablar solo de comandos sin explicar cómo funciona el repositorio local. Antes de los comandos, describe dónde vive, qué guarda y qué no puede hacer.
Verifica que funciona antes de seguir

6

Describe el versionamiento remoto (indicador 3)

Tiempo estimado: 15 min

El tercer indicador pide describir las características del versionamiento remoto. Aquí aparece lo que el repositorio local no puede darte. Cubre:

  • Ubicación: alojado en un servidor, identificado con una URL (https o SSH).
  • Colaboración: varias personas suben y bajan cambios, con permisos.
  • Respaldo: una copia fuera de tu equipo.
  • Sincronización: push, pull, fetch y clone; requiere internet.
  • Herramientas extra: pull requests, issues y automatización (CI/CD).
  • Límite: depende de la red y de los permisos.
Características del versionamiento remoto (modelo)
El repositorio remoto de TechStore Pro se aloja en GitHub y se identifica con una URL https. Permite que los tres integrantes compartan su trabajo con git push y lo reciban con git pull, y guarda una copia fuera de los equipos. Además ofrece pull requests para revisar el código antes de unirlo a la rama principal. Depende de la conexión a internet y de los permisos de cada integrante.
Error frecuente: describir GitHub como «una página para guardar archivos». Habla del repositorio remoto: qué contiene, quién accede y cómo se sincroniza con el local.

1. Introducción

En un proyecto de software, el control de versiones permite registrar los cambios del código y volver a un estado anterior cuando algo falla. Git trabaja con dos tipos de repositorio: el local, que vive en el equipo de cada desarrollador, y el remoto, alojado en una plataforma como GitHub, que permite compartir y respaldar el trabajo. TechStore Pro es una tienda en línea desarrollada por tres aprendices; por eso necesitan entender cómo se diferencian ambos repositorios y qué comandos los conectan.

2. Objetivo

Identificar las diferencias entre Git local y Git remoto y describir sus comandos básicos, para aplicarlos en el control de cambios del código del proyecto TechStore Pro.

3. Tipos de herramientas de versionamiento

Tabla 1. Tipos de herramientas de versionamiento

Local (sistema de control de versiones)El historial completo vive en el equipo, dentro de la carpeta .gitGitSíSe selecciona: registrar versiones en cada equipo, incluso sin conexión
Remoto (plataforma de alojamiento)Servicio en la nube que aloja repositorios Git y añade colaboraciónGitHubNoSe selecciona: compartir, respaldar y revisar código en equipo

Para TechStore Pro se selecciona Git como herramienta local, porque permite trabajar sin conexión, y GitHub como plataforma remota, porque facilita compartir el código y revisarlo mediante pull requests.

4. Características del versionamiento local

El repositorio local de TechStore Pro vive en la carpeta .git de cada equipo. Permite registrar versiones con git commit sin conexión a internet, consultar el historial con git log y crear ramas para probar funciones nuevas. Es privado y su límite es que no sirve como respaldo.

5. Características del versionamiento remoto

El repositorio remoto se aloja en GitHub y se identifica con una URL https. Permite compartir el trabajo con git push, recibirlo con git pull y mantener una copia fuera de los equipos. Ofrece pull requests para revisar el código. Depende de la conexión a internet y de los permisos.

Dónde estáEn el computador del desarrollador (carpeta .git)En un servidor en la nube (GitHub)
¿Necesita internet?No, salvo para compartirSí, para subir o bajar cambios
Quién accedeSolo el dueño del equipoEl equipo, según los permisos
Función principalTrabajar y registrar versiones del códigoCompartir, respaldar y colaborar
VelocidadInmediataDepende de la conexión
ColaboraciónNo directaPull requests, issues y revisión de código
RespaldoNo: si el equipo falla se pierde el historialSí: la copia queda fuera de los equipos
Comandos típicosinit, add, commit, status, log, branchremote, clone, push, pull, fetch

7.1 Comandos de Git local

Tabla 3. Comandos básicos de Git local

ComandoQué haceCuándo se usaEjemplo
git initCrea un repositorio local (carpeta .git) en el proyectoUna vez, al empezar un proyectogit init
git statusMuestra qué archivos cambiaron y cuáles están preparadosAntes de cada add y commitgit status
git addPasa archivos al staging para el próximo commitCuando un cambio está listo para guardarsegit add README.md

7.2 Comandos de Git remoto

Tabla 4. Comandos básicos de Git remoto

ComandoQué haceCuándo se usaEjemplo

8. Conclusiones

Git local y Git remoto se complementan: el repositorio local permite trabajar y registrar versiones sin conexión, y el remoto permite compartir, respaldar y colaborar. Entender sus diferencias y los comandos que los conectan es la base para mantener un flujo de trabajo ordenado.
