1. Introducción al Lenguaje SQL: Arquitectura DDL vs DML

El lenguaje estándar SQL (Structured Query Language) se estructura en dos subconjuntos fundamentales para garantizar la separación de responsabilidades entre la arquitectura física del almacén de datos y la gestión transaccional de registros:

Subconjunto Propósito Central Sentencias Clave Impacto en el SGBD
DDL (Data Definition Language) Crea, altera y elimina metadatos y estructuras físicas (tablas, columnas, restricciones, esquemas). CREATE, ALTER, DROP, TRUNCATE Afecta el catálogo del sistema. Es auto-commit (no reversible por rollback tradicional).
DML (Data Manipulation Language) Inserta, consulta, modifica y elimina los datos alojados en las filas de las tablas. INSERT, SELECT, UPDATE, DELETE Opera dentro de transacciones ACID (`COMMIT` / `ROLLBACK`).
Regla de Oro de la Arquitectura DDL: Siempre debes crear primero las tablas maestras o padres (aquellas que no tienen llaves foráneas, ej: roles, categorias) antes de crear las tablas hijas dependientes (ej: usuarios, productos, pedidos). Intentar crear una FK hacia una tabla inexistente provocará el error de MySQL Error Code: 1215 - Cannot add foreign key constraint.

2. Sentencias DDL Esenciales en MySQL

A continuación se detallan las sentencias fundamentales para crear y gobernar la base de datos con codificación internacional completa:

2.1. Creación del Schema con UTF8MB4

La codificación utf8mb4 es el estándar actual en el desarrollo web profesional, pues admite caracteres especiales, acentos y emojis en 4 bytes:

sql/01_crear_schema.sql 
-- Crear base de datos si no existe con codificación moderna
CREATE DATABASE IF NOT EXISTS techstore_db
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_unicode_ci;

-- Seleccionar la base de datos para trabajar
USE techstore_db;

2.2. Modificación de Estructura con ALTER TABLE

Permite alterar columnas, tipos de datos o agregar restricciones a tablas que ya contienen información sin necesidad de recrearlas:

sql/02_alter_table.sql 
-- Agregar una columna con posición controlada
ALTER TABLE usuarios 
ADD COLUMN telefono VARCHAR(20) NULL AFTER email;

-- Modificar el tipo de dato o nulabilidad
ALTER TABLE usuarios 
MODIFY COLUMN nombres VARCHAR(70) NOT NULL;

-- Agregar una restricción UNIQUE nombrada
ALTER TABLE usuarios 
ADD CONSTRAINT uq_usuario_documento UNIQUE (documento);

3. Restricciones de Integridad (Constraints) en Motores Relacionales

Las restricciones son las reglas de negocio codificadas a nivel del motor relacional. Evitan la corrupción de datos incluso si el aplicativo Front-End o Back-End falla:

Restricción Función Técnica Ejemplo de Negocio en TechStore Pro
PRIMARY KEY (PK) Identificador único no nulo que crea un índice clustered físico. id_producto INT AUTO_INCREMENT PRIMARY KEY
FOREIGN KEY (FK) Establece relación de dependencia referencial con la PK de otra tabla. FOREIGN KEY (id_categoria) REFERENCES categorias(id_categoria)
UNIQUE Impide duplicidad de valores en una columna distinta de la PK. sku VARCHAR(35) NOT NULL UNIQUE, email UNIQUE
CHECK Valida una expresión booleana antes de aceptar la fila. CONSTRAINT chk_precio CHECK (precio > 0.00)
NOT NULL Exige que la celda tenga un valor asignado (sin estados vacíos). nombre VARCHAR(120) NOT NULL
DEFAULT Inyecta un valor automático si el cliente no lo especifica. stock INT DEFAULT 0, fecha DEFAULT CURRENT_TIMESTAMP

3.1. Acciones Referenciales: ON DELETE CASCADE vs RESTRICT

Criterio de Arquitectura en Producción:
• Usa ON DELETE CASCADE exclusivamente en relaciones donde el registro hijo no tiene sentido sin el padre (ej: borrar una orden elimina automáticamente sus renglones en detalle_pedidos).
• Usa ON DELETE RESTRICT en tablas maestras críticas (ej: impedir borrar una categoria si aún existen productos vinculados a ella).

4. Caso Práctico TechStore Pro React: Estructura Completa

Script DDL profesional y probado que implementa las 6 tablas relacionales del proyecto formativo:

sql/techstore_db_completo.sql 
-- Tabla Categorías
CREATE TABLE categorias (
    id_categoria INT AUTO_INCREMENT PRIMARY KEY,
    slug VARCHAR(60) NOT NULL UNIQUE,
    nombre VARCHAR(60) NOT NULL UNIQUE,
    descripcion TEXT,
    activo BOOLEAN NOT NULL DEFAULT TRUE
) ENGINE=InnoDB;

-- Tabla Productos con Llave Foránea y Restricción CHECK
CREATE TABLE productos (
    id_producto INT AUTO_INCREMENT PRIMARY KEY,
    sku VARCHAR(35) NOT NULL UNIQUE,
    nombre VARCHAR(120) NOT NULL,
    precio DECIMAL(12,2) NOT NULL,
    stock INT NOT NULL DEFAULT 0,
    id_categoria INT NOT NULL,
    estado ENUM('Disponible', 'Agotado', 'Descontinuado') NOT NULL DEFAULT 'Disponible',
    CONSTRAINT chk_precio_positivo CHECK (precio > 0.00),
    CONSTRAINT chk_stock_valido CHECK (stock >= 0),
    CONSTRAINT fk_productos_categorias
        FOREIGN KEY (id_categoria) REFERENCES categorias(id_categoria)
        ON DELETE RESTRICT ON UPDATE CASCADE
) ENGINE=InnoDB;

-- Tabla Pedidos (Cabecera)
CREATE TABLE pedidos (
    id_pedido INT AUTO_INCREMENT PRIMARY KEY,
    numero_orden VARCHAR(30) NOT NULL UNIQUE,
    id_usuario INT NOT NULL,
    fecha_pedido DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    total DECIMAL(14,2) NOT NULL DEFAULT 0.00,
    estado ENUM('Pendiente', 'Pagado', 'Enviado', 'Entregado') DEFAULT 'Pendiente',
    CONSTRAINT fk_pedidos_usuarios
        FOREIGN KEY (id_usuario) REFERENCES usuarios(id_usuario)
        ON DELETE RESTRICT ON UPDATE CASCADE
) ENGINE=InnoDB;

-- Tabla Detalle de Pedidos (N:M con cálculo de subtotal)
CREATE TABLE detalle_pedidos (
    id_detalle INT AUTO_INCREMENT PRIMARY KEY,
    id_pedido INT NOT NULL,
    id_producto INT NOT NULL,
    cantidad INT NOT NULL DEFAULT 1,
    precio_unitario DECIMAL(12,2) NOT NULL,
    subtotal DECIMAL(14,2) GENERATED ALWAYS AS (cantidad * precio_unitario) STORED,
    CONSTRAINT chk_cantidad_minima CHECK (cantidad > 0),
    CONSTRAINT fk_detalle_pedidos
        FOREIGN KEY (id_pedido) REFERENCES pedidos(id_pedido)
        ON DELETE CASCADE ON UPDATE CASCADE,
    CONSTRAINT fk_detalle_productos
        FOREIGN KEY (id_producto) REFERENCES productos(id_producto)
        ON DELETE RESTRICT ON UPDATE CASCADE
) ENGINE=InnoDB;

5. Manipulación Transaccional DML (INSERT, SELECT, UPDATE, DELETE)

Una vez levantada la estructura física, procedemos a poblar datos semilla y consultar la base de datos:

5.1. Consulta Multitabla con INNER JOIN

Permite consolidar la información normalizada en reportes legibles para el usuario o la API en Node.js/Express:

sql/03_select_inner_join.sql 
-- Consulta de Órdenes detalladas con datos de Cliente y Producto
SELECT 
    ped.numero_orden,
    CONCAT(u.nombres, ' ', u.apellidos) AS cliente,
    prod.nombre AS item_comprado,
    det.cantidad,
    det.precio_unitario,
    det.subtotal,
    ped.estado AS estado_orden
FROM pedidos ped
INNER JOIN usuarios u ON ped.id_usuario = u.id_usuario
INNER JOIN detalle_pedidos det ON ped.id_pedido = det.id_pedido
INNER JOIN productos prod ON det.id_producto = prod.id_producto
ORDER BY ped.fecha_pedido DESC;

5.2. Actualizaciones y Eliminaciones Seguras

Alerta de Seguridad en Producción: Jamás ejecutes una sentencia UPDATE o DELETE sin la cláusula WHERE filtrada por la clave primaria (`PRIMARY KEY`). Omitir el `WHERE` afectará o destruirá todas las filas de la tabla de forma irreversible.

6. Matriz de Errores Técnicos Frecuentes y Cómo Prevenirlos

Error Técnico / Síntoma Causa Raíz Solución Estándar Aplicada
Error Code: 1215 - Cannot add FK Incompatibilidad de tipos entre la PK padre y la FK hija (ej: INT vs BIGINT o UNSIGNED desigual). Asegurar que la columna foránea tenga exactamente el mismo tipo de dato y signo que la llave primaria.
Error Code: 3819 - Check violated El valor a insertar no satisface la regla matemática (ej. precio negativo o stock < 0). Validar los datos en el aplicativo antes de enviar la sentencia `INSERT`/`UPDATE`.
Error Code: 1451 - Cannot delete row Se intenta borrar una fila padre con `ON DELETE RESTRICT` que todavía tiene hijos asociados. Eliminar o reasignar primero los registros hijos antes de suprimir el registro padre.
Pérdida de acentos o caracteres '??' Base de datos creada con `latin1` o `utf8` de 3 bytes obsoleto. Usar siempre utf8mb4 con cotejamiento utf8mb4_unicode_ci.

9. Anexo Opcional: Guía Completa de MySQL Workbench

Recuerda que en el programa ADSO puedes realizar y aprobar toda la práctica ejecutando directamente tu script en el IDE Antigravity / Extensión Database Client conectado a XAMPP. Sin embargo, si deseas generar los Diagramas EER visuales para enriquecer tu informe de la evidencia AA2-EV02 o prefieres utilizar una herramienta de escritorio dedicada, sigue esta guía paso a paso:

¿Por qué MySQL Workbench es opcional pero valioso?

Ambas herramientas se conectan exactamente al mismo servicio local de MySQL (puerto 3306). La gran ventaja de MySQL Workbench es su motor de Ingeniería Inversa (Reverse Engineer), el cual lee tus tablas SQL físicas y dibuja automáticamente el diagrama relacional completo con todas sus llaves foráneas.

Criterio IDE Antigravity / Extensión SQL (Recomendado en Clase) MySQL Workbench Community (Opcional para EER)
Instalación Inmediata desde el marketplace del editor (0 MB adicionales de instalador). Requiere instalador .msi (~45 MB) y paquetes Visual C++ de Windows.
Flujo de Desarrollo Escribes, ejecutas y versionas con Git en la misma ventana de código. Aplicación de escritorio externa separada del código fuente del proyecto.
Poder de Diagramación Visor tabular y árbol de base de datos. Modelador visual EER avanzado con exportación a PDF y PNG.

3 Instalación y Conexión con XAMPP

  1. Abre el instalador mysql-workbench-community-8.0.x-winx64.msi. Presiona Next, selecciona la instalación Complete y haz clic en Install.
  2. Asegúrate de que en el Panel de Control de XAMPP el módulo de MySQL esté iniciado en verde (puerto 3306).
  3. Abre MySQL Workbench. En la pantalla inicial verás un recuadro gris llamado MySQL Connections.
  4. Haz clic en el ícono de suma [+] junto a "MySQL Connections" para configurar tu acceso local:

4 Ejecución del Script y Generación del Diagrama EER (Para EV02)

  1. Entra a la conexión XAMPP Localhost recién creada.
  2. Presiona Ctrl + Shift + O (o ve al menú File ➔ Open SQL Script...) y selecciona el archivo techstore_db_completo.sql.
  3. Haz clic en el botón Execute SQL Script (icono de ejecución en la barra de herramientas, o presiona Ctrl + Shift + Enter) para ejecutar todo el script. Verás una hilera de checks verdes en el panel inferior de Action Output.
  4. Para generar el diagrama relacional automático: ve al menú superior Database ➔ Reverse Engineer... (o presiona Ctrl + R).
  5. Haz clic en Next, selecciona la base de datos techstore_db, y presiona Next ➔ Execute ➔ Next ➔ Finish.
  6. Se abrirá una pestaña visual con el Diagrama EER mostrando las tablas, sus columnas y las líneas de unión con patas de gallo. Ve a File ➔ Export ➔ Export as PNG... para guardar la imagen que adjuntarás en tu informe de la evidencia AA2-EV02.
