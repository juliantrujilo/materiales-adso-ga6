2. Tus Herramientas: MongoDB Compass y la Consola Mongosh

MongoDB Compass es la interfaz visual (GUI) oficial de MongoDB. Dentro de ella, el botón 'Open MongoDB shell' (esquina superior derecha de la ventana) abre una consola Mongosh ya conectada a tu base de datos, en una pestaña nueva — sin necesidad de instalar ningún programa aparte.

¿Por qué usamos solo la consola embebida de Compass?
El binario independiente de mongosh (para abrir en una terminal normal de PowerShell/CMD) es un paquete aparte que no viene instalado junto con Compass. Para evitar errores de "mongosh no se reconoce como un comando", en esta sesión usamos exclusivamente la vía garantizada: el botón 'Open MongoDB shell' dentro de Compass.

Al abrir la consola, ya estás conectado

La consola embebida ejecuta automáticamente use("techstore_nosql") al abrirse, y el prompt queda como techstore_nosql>, listo para trabajar sin escribir nada más.

3. El Ciclo de 3 Tiempos: Buscar → Actuar → Buscar

Analogía Didáctica: "Antes y Después de la Foto". Nunca modifiques o elimines un documento a ciegas. El flujo profesional y el que exige tu evidencia es siempre el mismo, sin importar si es un Update o un Delete:

🔁 El Ciclo que Repetirás en Toda la Sesión
1. BUSCAR (find / findOne) → Confirmas el estado ANTES del cambio. 2. ACTUAR (updateOne / deleteOne) → Ejecutas la modificación o eliminación. 3. BUSCAR DE NUEVO (find / findOne) → Confirmas el estado DESPUÉS del cambio.
¿Por qué nunca filtras por nombre o texto libre?
Un campo de texto libre (nombre, título) puede repetirse entre documentos o tener un error de tipeo — nunca garantiza que afectes exactamente 1 documento. Filtra siempre por un identificador único: el _id que MongoDB genera automáticamente al insertar, o un campo de negocio único como sku.

4. Create — Inserción en Lote con insertMany()

insertMany() recibe un arreglo [ ] de varios objetos { } y los inserta todos en una sola operación — a diferencia de insertOne(), que solo guarda un documento.

📄 Insertar 5 usuarios reales de TechStore
db.usuarios.insertMany([ { "email": "carlos.perez@techstore.co", "nombre_completo": "Carlos Andrés Pérez Sterling", "activo": true }, { "email": "laura.gomez@techstore.co", "nombre_completo": "Laura Marcela Gómez Quintero", "activo": true }, { "email": "julian.morales@techstore.co", "nombre_completo": "Julián David Morales Rivera", "activo": false }, { "email": "diana.rojas@techstore.co", "nombre_completo": "Diana Carolina Rojas Peña", "activo": true }, { "email": "andres.cabrera@techstore.co", "nombre_completo": "Andrés Felipe Cabrera Medina", "activo": true } ]);
2 errores comunes que debes evitar:
• Corchete extra al inicio: el arreglo que copies ya trae su propio [ — no escribas tú otro antes, o quedan corchetes dobles [[ ... ]] y Mongosh marca SyntaxError.
• Falta cerrar al final: el arreglo pegado termina en ] — tú debes añadir a mano el cierre ); justo después. El comando completo debe terminar exactamente en ]);.

Punto de partida limpio

Si ya tenías datos cargados desde la Sesión 3, vacía primero las 3 colecciones para evitar duplicados: db.usuarios.deleteMany({}), db.productos.deleteMany({}), db.ordenes.deleteMany({}).

5. Read — Consultas con Filtros MQL

El método find() es el equivalente directo a la cláusula WHERE de SQL.

ComandoOperadorResultado Esperado
find({ activo: true })Booleano4 de 5 productos (oculta inactivos)
find({ precio: { $gt: 2000000 } })Rango superior1 de 5 productos
find({ precio: { $gte:..., $lte:... } })Rango intermedio2 de 5 productos
find({ "especificaciones.ram_gb": 32 })Notación de punto1 producto (subdocumento embebido)
find({ etiquetas: "gamer" })Filtro en arreglos3 productos
find({ _id: ObjectId("...") })Identificador interno1 producto (el que MongoDB generó al insertar)
findOne({ sku: "TEC-MEC-02" })Identificador de negocio1 documento completo
_id vs sku — ¿cuál es la diferencia?
El _id es un ObjectId que MongoDB genera solo y nunca se repite entre documentos; el sku es un identificador que tú defines en tu modelo de datos (equivalente a una clave de negocio en SQL).

6. Update — Atomicidad con $set y $inc

La rúbrica exige actualizar explícitamente el primer y el último registro insertado, siguiendo siempre el ciclo de 3 tiempos.

🔁 Ciclo completo: buscar → actualizar → buscar
// 1. Buscar ANTES: db.productos.find({ sku: "LAP-PRO-01" }); // 2. Actualizar: db.productos.updateOne( { sku: "LAP-PRO-01" }, { $set: { precio: 4990000.00, stock: 12 } } ); // 3. Buscar DESPUÉS para confirmar: db.productos.find({ sku: "LAP-PRO-01" });

$set vs $inc — no son lo mismo

$set reemplaza el valor por uno nuevo que tú escribes. $inc suma al valor existente — por ejemplo $inc: { veces_actualizado: 1 } toma el contador actual y le suma 1 (si el campo no existe, MongoDB lo crea empezando en 1).

7. Delete — Eliminación Segura con Filtro Estricto

La rúbrica exige explícitamente eliminar el tercer documento insertado, siguiendo el mismo ciclo de 3 tiempos.

🔁 Ciclo completo: buscar → eliminar → buscar
// 1. Buscar ANTES de eliminar: db.productos.find({ sku: "MON-GAM-03" }); // 2. Eliminar con filtro específico: db.productos.deleteOne({ sku: "MON-GAM-03" }); // Retorno esperado: { acknowledged: true, deletedCount: 1 } // 3. Buscar DESPUÉS (debe devolver vacío): db.productos.find({ sku: "MON-GAM-03" }); // 4. Verificar el conteo total: db.productos.countDocuments(); // Debe mostrar 4 (si partiste de 5 documentos)
Prohibido en la entrega: Nunca ejecutes db.productos.deleteMany({}) (filtro vacío) durante tu grabación — elimina TODA la colección de forma instantánea e irreversible.

8. Exportación de Colecciones a Archivos JSON

Para adjuntar los esquemas en Zajuna (Evidencia AA1-EV03), exportamos tus colecciones usando el botón visual EXPORT DATA de Compass — no se usa la línea de comandos mongoexport porque ese binario, igual que el mongosh standalone, no viene instalado por defecto.

Paso 1 — Seleccionar la colección: En el panel lateral de Compass, haz clic sobre la colección a exportar (empieza por usuarios).
Paso 2 — Abrir EXPORT DATA: En la barra de herramientas, clic en 'EXPORT DATA ▾' y elige 'Export the full collection'.
Paso 3 — Confirmar formato JSON: Deja todos los campos seleccionados y asegúrate de que el formato marcado sea JSON, nunca CSV.
Paso 4 — Guardar y repetir: Guarda como usuarios.json y repite el mismo proceso con productos y ordenes.
