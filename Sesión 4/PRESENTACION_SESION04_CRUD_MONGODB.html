Bloque 1 · Fundamento Conceptual

El Ciclo CRUD en Bases de Datos Documentales

Cómo se traduce el ciclo universal de manipulación de información al modelo NoSQL de MongoDB.

Operación CRUD Equivalente MySQL (Sesión 2) Método MQL en Mongosh Acción en Compass (GUI)
C · Create (Crear) INSERT INTO productos (...) db.productos.insertOne({...}) Botón verde ADD DATA ▾ -> Insert
R · Read (Leer/Consultar) SELECT * FROM productos WHERE... db.productos.find({ activo: true }) Barra superior Filter { }
U · Update (Actualizar) UPDATE productos SET precio = ... db.productos.updateOne(..., { $set: {...} }) Icono del lápiz Edit Document
D · Delete (Eliminar) DELETE FROM productos WHERE ... db.productos.deleteOne({ sku: "..." }) Icono de papelera Delete Document
💡 Atomicidad a Nivel de Documento (Ventaja de MongoDB):

A diferencia de SQL donde actualizar una orden y sus ítems requiere abrir transacciones sobre múltiples tablas (ordenes e items_orden), en MongoDB la orden almacena sus ítems embebidos en un solo documento BSON. Por tanto, cualquier inserción o actualización es 100% atómica por defecto, sin overhead de bloqueos relacionales.

Bloque 2 · Operaciones MQL

Operación Create: Inserción Individual y por Lote

Cómo incorporar nuevos documentos en colecciones existentes sin alterar esquemas previos.

db.collection.insertOne()

Inserción Unitaria (1 Documento)

Inserta un único objeto BSON. Si no se especifica el campo _id, MongoDB genera automáticamente un ObjectId de 12 bytes único en el cluster. 

db.productos.insertOne({
  sku: "TAB-PRO-06",
  titulo: "Tablet Digitalizadora 2K Pro",
  precio: 1450000.00,
  stock: 20,
  activo: true
});
db.collection.insertMany()

Inserción en Lote (Arreglo [])

Recibe un arreglo de múltiples documentos JSON [{...}, {...}]. Es el método más eficiente para cargas iniciales o migraciones de datos. 

db.productos.insertMany([
  { sku: "CAM-4K-07", precio: 480000 },
  { sku: "HUB-USB-08", precio: 120000 }
]);
⚠️ Regla de Oro en Inserciones NoSQL: Asegúrate de que los valores numéricos de precio y stock se escriban sin comillas (ej: 1450000.00 en lugar de "1450000.00"). De lo contrario, MongoDB los almacenará como Strings y fallarán las consultas de rango numérico ($gt, $lt).
Bloque 2 · Operaciones MQL

Operación Read: Consultas con Operadores MQL

El lenguaje de consultas MQL reemplaza las cláusulas WHERE y JOIN de SQL mediante objetos JSON.

1. Operadores de Rango

Filtran valores mayores, menores o iguales sin conversiones: 

// Precios > 1.000.000 COP:
{ precio: { $gt: 1000000 } }

// Entre 300k y 1M COP:
{ precio: { 
  $gte: 300000, 
  $lte: 1000000 
} }

2. Notación de Punto

Permite inspeccionar campos dentro de subdocumentos embebidos: 

// RAM de 32GB en specs:
{ "especificaciones.ram_gb": 32 }

// Clientes en Garzón:
{ "direccion_envio.ciudad": "Garzón" }

3. Consultas en Arreglos

Evalúa si un elemento existe dentro de un array de strings: 

// Productos con tag gamer:
{ etiquetas: "gamer" }

// Múltiples tags con $in:
{ etiquetas: { 
  $in: ["diseno", "gamer"] 
} }
Diferencia Clave con SQL: En SQL, consultar la ciudad de un cliente requería SELECT * FROM clientes c JOIN direcciones d ON c.id = d.cliente_id WHERE d.ciudad = 'Garzón'. En MongoDB, gracias a los subdocumentos embebidos, se consulta directamente con { "direccion_envio.ciudad": "Garzón" } en un único acceso a disco.
Bloque 2 · Operaciones MQL

Operaciones Update & Delete: Mutación Segura

Reglas técnicas para evitar la pérdida accidental de datos en bases de datos NoSQL.

db.collection.updateOne()

Actualización con Operador $set

¡La Regla de Oro de MongoDB! Para modificar atributos específicos siempre debes usar el operador $set. Si pasas un objeto sin $set, MongoDB reemplazará el documento completo, eliminando todos los demás campos. 

db.productos.updateOne(
  { sku: "LAP-PRO-01" },
  { 
    $set: { 
      precio: 4990000.00,
      stock: 12 
    },
    $currentDate: { ultima_modificacion: true }
  }
);
db.collection.deleteOne()

Eliminación Segura y Restrictiva

Elimina el primer documento que coincida con el filtro de búsqueda. Se recomienda filtrar siempre por campos de identidad única como _id o sku para evitar eliminar registros equivocados. 

// Elimina producto descontinuado:
db.productos.deleteOne({ 
  sku: "HUB-USB-08" 
});

// Retorno esperado:
// { acknowledged: true, deletedCount: 1 }
🛑 Peligro Técnico: ¿Por qué deleteMany({}) está prohibido en producción? Ejecutar db.productos.deleteMany({}) sin un objeto de filtro eliminará absolutamente todos los documentos de la colección de manera instantánea e irreversible. Usa siempre filtros precisos.

db.productos.find({

db.productos.find({

db.productos.find({
  etiquetas: "diseno"
});

db.productos.find({}, { sku: 1, titulo: 1, precio: 1, _id: 0 });

Tabla de Parámetros de Operaciones CRUD en MongoDB:

Operación CRUD Sintaxis MQL / Interfaz Compass Efecto en la Base de Datos
Create (Crear) db.productos.insertOne({ ... }) o botón ADD DATA ▾ Inserta nuevo documento generando un _id ObjectId único e inmutable.
Read (Leer) db.productos.find({ precio: { $gt: 500000 } }) o barra FILTER Recupera un cursor con documentos coincidentes sin alterar el almacenamiento en disco.
Update (Modificar) db.productos.updateOne({ codigo: "..." }, { $set: { ... } }) Mutación atómica in-place del documento seleccionado mediante operadores $set o $inc.
Delete (Eliminar) db.productos.deleteOne({ codigo: "..." }) o ícono papelera Compass Remueve físicamente el documento de la colección. Requiere filtro específico para evitar borrados masivos.
