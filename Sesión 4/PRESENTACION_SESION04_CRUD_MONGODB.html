Bloque 1 · Fundamento Conceptual

El Ciclo CRUD en Bases de Datos Documentales

Cómo se traduce el ciclo universal de manipulación de información al modelo NoSQL de MongoDB.

Operación CRUD Equivalente MySQL (Sesión 2) Método MQL en Mongosh Acción en Compass (GUI)
C · Create (Crear) INSERT INTO productos (...) db.productos.insertOne({...}) Botón verde ADD DATA ▾ -> Insert
R · Read (Leer/Consultar) SELECT * FROM productos WHERE... db.productos.find({ activo: true }) Barra superior Filter { }
U · Update (Actualizar) UPDATE productos SET precio = ... db.productos.updateOne(..., { $set: {...} }) Icono del lápiz Edit Document
D · Delete (Eliminar) DELETE FROM productos WHERE ... db.productos.deleteOne({ sku: "..." }) Icono de papelera Delete Document
💡 ¿Por qué no se te "rompe" una orden a la mitad? (Ventaja de MongoDB):

Imagina que una orden con 3 productos fuera como una carpeta con hojas sueltas: la cabecera en una tabla ordenes y cada producto en hojas separadas dentro de items_orden. Si la luz se va justo cuando ya guardaste la cabecera pero aún faltaba guardar el tercer producto, te queda una orden coja: existe, pero le falta una pieza. En SQL, para evitar eso, tienes que "amarrar" esas dos tablas con una transacción antes de guardar.

En MongoDB tú guardas esa misma orden como un solo sobre cerrado: la cabecera y los 3 productos van embebidos dentro de un único documento BSON. Como es un solo objeto, Mongo lo escribe de un solo golpe — o queda guardado completo, o no queda guardado nada; nunca a medias. Eso es lo que significa "atómico por defecto": no es un término abstracto, es la garantía concreta de que jamás vas a encontrar una orden con 2 de 3 productos. Y como no hay nada que "amarrar" entre tablas, tampoco pagas el costo (overhead) de esos bloqueos que SQL necesita para sincronizar varias tablas a la vez.

Bloque 2 · Operaciones MQL

Operación Create: Inserción Individual y por Lote

Cómo incorporar nuevos documentos en colecciones existentes sin alterar esquemas previos.

db.collection.insertOne()

Inserción Unitaria (1 Documento)

Inserta un único objeto BSON. Si no se especifica el campo _id, MongoDB genera automáticamente un ObjectId de 12 bytes único en el cluster. 

db.productos.insertOne({
  sku: "TAB-PRO-06",
  titulo: "Tablet Digitalizadora 2K Pro",
  precio: 1450000.00,
  stock: 20,
  activo: true
});
db.collection.insertMany()

Inserción en Lote (Arreglo [])

Recibe un arreglo de múltiples documentos JSON [{...}, {...}]. Es el método más eficiente para cargas iniciales o migraciones de datos. 

db.productos.insertMany([
  { sku: "CAM-4K-07", precio: 480000 },
  { sku: "HUB-USB-08", precio: 120000 }
]);
⚠️ Regla de Oro en Inserciones NoSQL: Asegúrate de que los valores numéricos de precio y stock se escriban sin comillas (ej: 1450000.00 en lugar de "1450000.00"). De lo contrario, MongoDB los almacenará como Strings y fallarán las consultas de rango numérico ($gt, $lt).
Bloque 2 · Operaciones MQL

Operación Read: Consultas con Operadores MQL

El lenguaje de consultas MQL reemplaza las cláusulas WHERE y JOIN de SQL mediante objetos JSON.

1. Operadores de Rango

Filtran valores mayores, menores o iguales sin conversiones: 

// Precios > 1.000.000 COP:
{ precio: { $gt: 1000000 } }

// Entre 300k y 1M COP:
{ precio: { 
  $gte: 300000, 
  $lte: 1000000 
} }

2. Notación de Punto

Permite inspeccionar campos dentro de subdocumentos embebidos: 

// RAM de 32GB en specs:
{ "especificaciones.ram_gb": 32 }

// Clientes en Garzón:
{ "direccion_envio.ciudad": "Garzón" }

3. Consultas en Arreglos

Evalúa si un elemento existe dentro de un array de strings: 

// Productos con tag gamer:
{ etiquetas: "gamer" }

// Múltiples tags con $in:
{ etiquetas: { 
  $in: ["diseno", "gamer"] 
} }
Diferencia Clave con SQL: En SQL, consultar la ciudad de un cliente requería SELECT * FROM clientes c JOIN direcciones d ON c.id = d.cliente_id WHERE d.ciudad = 'Garzón'. En MongoDB, gracias a los subdocumentos embebidos, se consulta directamente con { "direccion_envio.ciudad": "Garzón" } en un único acceso a disco.
Bloque 2 · Operaciones MQL

Operaciones Update & Delete: Mutación Segura

Reglas técnicas para evitar la pérdida accidental de datos en bases de datos NoSQL.

db.collection.updateOne()

Actualización con Operador $set

¡La Regla de Oro de MongoDB! Para modificar atributos específicos siempre debes usar el operador $set. Si pasas un objeto sin $set, MongoDB reemplazará el documento completo, eliminando todos los demás campos. 

db.productos.updateOne(
  { sku: "LAP-PRO-01" },
  { 
    $set: { 
      precio: 4990000.00,
      stock: 12 
    },
    $currentDate: { ultima_modificacion: true }
  }
);
db.collection.deleteOne()

Eliminación Segura y Restrictiva

Elimina el primer documento que coincida con el filtro de búsqueda. Se recomienda filtrar siempre por campos de identidad única como _id o sku para evitar eliminar registros equivocados. 

// Elimina producto descontinuado:
db.productos.deleteOne({ 
  sku: "HUB-USB-08" 
});

// Retorno esperado:
// { acknowledged: true, deletedCount: 1 }
🛑 Peligro Técnico: ¿Por qué deleteMany({}) está prohibido en producción? Ejecutar db.productos.deleteMany({}) sin un objeto de filtro eliminará absolutamente todos los documentos de la colección de manera instantánea e irreversible. Usa siempre filtros precisos.

💡 ¿Cómo ejecutas tú cada una de estas 5 consultas find()?

Este codebox es de referencia, pero son las mismas consultas que ya usaste en el Paso 5 del stepper — aquí te explicamos la diferencia clave entre ejecutarlas en Mongosh y en la barra Filter de Compass:

  • Vía Mongosh (terminal o consola >_ MONGOSH de Compass): Copia la línea completa tal como está en el codebox, incluyendo db.productos.find(...) y el punto y coma final, y pégala directo en la consola.
  • Vía barra Filter de Compass (visual): La barra Filter ya asume que estás dentro de db.productos.find(), así que nunca escribas db.productos.find(...) ahí — solo pega el objeto que va entre los paréntesis. Por ejemplo, para la consulta 1 solo escribes { stock: { $gt: 0 } } y pulsas Find.
  • Consultas 2, 3 y 4 (mismo truco): Toma solo el contenido entre find({ ... }) y pégalo en la barra Filter: { precio: { $gte: 400000.00, $lte: 2000000.00 } }, { "especificaciones.ram_gb": 32 }, { etiquetas: "diseno" } respectivamente.
  • Consulta 5 (proyección, caso especial): La barra Filter de Compass tiene un segundo campo aparte llamado 'Project' (debajo o al lado de Filter). Ahí es donde va { sku: 1, titulo: 1, precio: 1, _id: 0 }; el campo Filter en este caso se deja vacío {} porque no estás filtrando, solo eligiendo qué campos mostrar.
  • Resultado esperado: cada consulta reduce visualmente el contador de documentos en Compass (o la lista impresa en Mongosh) según cuántos de tus 5 productos cumplen la condición — compáralo con lo que ya viste en el Paso 5 del stepper para verificar que coincide.

Codebox 3: Modificación y Eliminación Segura (Update & Delete)

Operadores de mutación atómica ($set, $inc) y eliminación selectiva con comprobación de estado.

03_update_delete_mql.js
MQL · MongoDB
1// 1. UPDATE: Actualizar precio y stock del Portátil:
2db.productos.updateOne(
3  { sku: "LAP-PRO-01" },
4  {
5    $set: { precio: 4990000.00, stock: 12 },
6    $inc: { veces_actualizado: 1 }
7  }
8);
9
10// 2. UPDATE: Reactivar producto agotado (Monitor):
11db.productos.updateOne(
12  { sku: "MON-GAM-03" },
13  { $set: { stock: 8, activo: true } }
14);
15
16// 3. DELETE: Eliminar producto descontinuado de prueba:
17db.productos.deleteOne({ sku: "TEC-MEC-02" });
18
19// 4. READ FINAL: Verificar conteo de la colección:
20db.productos.countDocuments();
💡 Este script es de referencia — así se ejecutan $set, $inc y deleteOne() en la vida real:

Igual que los codeboxes anteriores, este no es obligatorio para tu video (ya hiciste update y delete en el Paso 5 y 6 del stepper). Pero si quieres practicarlo aparte sobre tu colección real, así funciona cada operador:

  • $set vs $inc (la diferencia clave): $set reemplaza el valor de un campo por uno nuevo que tú escribes (ej: precio: 4990000.00 deja el precio exactamente en ese número). $inc en cambio suma al valor que ya existía (ej: veces_actualizado: 1 toma el número actual de ese campo y le suma 1 — si el campo no existe aún, MongoDB lo crea empezando en 1).
  • Vía Mongosh: Copia cada bloque completo (desde db.productos.updateOne(...) o deleteOne(...) hasta su punto y coma) y pégalo en la consola. Puedes combinar $set e $inc en la misma operación, como ves en la consulta 1.
  • Vía Compass (updateOne visual): Compass no tiene un botón directo para "$set/$inc" — para lograr el mismo efecto visualmente, ubica el documento, clic en el lápiz 'Edit Document', cambia el valor del campo a mano (eso equivale a $set) y pulsa Update. Para sumar un contador ($inc) tendrías que calcular tú el nuevo número y escribirlo — por eso $inc es más cómodo desde Mongosh.
  • Vía Compass (deleteOne visual): Ubica el documento con sku: "TEC-MEC-02", pasa el cursor sobre él, clic en el ícono de la papelera 🗑️ y confirma en el recuadro rojo.
  • countDocuments() al final: Siempre que elimines algo, cierra con db.productos.countDocuments() para dejar evidencia de que el conteo bajó exactamente en 1 — ese hábito de verificación es justo lo que pide la rúbrica.

Tabla de Parámetros de Operaciones CRUD en MongoDB:

Operación CRUD Sintaxis en Mongosh Efecto en la Base de Datos
Create (Crear) db.productos.insertOne({ ... }) Inserta nuevo documento generando un _id ObjectId único e inmutable.
Read (Leer) db.productos.find({ precio: { $gt: 500000 } }) Recupera un cursor con documentos coincidentes sin alterar el almacenamiento en disco.
